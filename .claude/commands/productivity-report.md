# Productivity Report

Generates a SPACE-framework productivity report covering Delivered Capability velocity, DORA performance metrics, LOC efficiency, and spec pipeline health. Optionally compares against a baseline period.

**Framework:** SPACE (Satisfaction, Performance, Activity, Communication, Efficiency) — see ADR-008 and `.claude/metrics/README.md`.

Execute the following steps in order:

## 1. Refresh All Metrics

Run the four productivity scripts to ensure `usage-stats.toml` is up to date:

```bash
python3 .claude/scripts/loc_compute.py
python3 .claude/scripts/spec_pipeline.py
python3 .claude/scripts/dc_counter.py --json | python3 .claude/scripts/dc_timeline.py
python3 .claude/scripts/dora_metrics.py
python3 .claude/scripts/loc_churn.py
```

## 2. Read Metrics

Read `.claude/metrics/usage-stats.toml` to get the current values for all sections: `[productivity]`, `[spec_pipeline]`, `[pr_review_quality]`, `[dc_timeline]`, `[dora_metrics]`, `[loc_churn]`.

## 3. Parse Arguments

If the user passed `--baseline YYYY-WNN`, locate that period in `[[dc_timeline.periods]]` and compute the delta vs. the most recent period. Otherwise, compare the most recent full period against the 4-week moving average.

## 4. Prompt for Satisfaction Score

Ask the user: "On a scale of 1–5, how would you rate your overall satisfaction with development velocity this period? (1 = very frustrated, 5 = very satisfied)"

Record the score. If the user skips, use `null`.

## 5. Generate Report

Produce a Markdown report with this structure:

```markdown
# Productivity Report — YYYY-WNN

**Generated:** YYYY-MM-DD | **Framework:** SPACE (ADR-008)

---

## Overall Score

| Dimension | Metric | Value | Trend |
|-----------|--------|-------|-------|
| S — Satisfaction | Self-rating | N/5 | — |
| P — Performance | Deployment frequency | N.N feat/week | ↑/↓/→ |
| P — Performance | Lead time (median) | N.N hours | ↑/↓/→ |
| A — Activity | DC velocity (weighted) | N.N DCs/week | ↑/↓/→ |
| A — Activity | Specs implemented (MTD) | N | ↑/↓/→ |
| C — Communication | PR accept ratio | N% | ↑/↓/→ |
| E — Efficiency | Test/prod LOC ratio | N.N% | ↑/↓/→ |
| E — Efficiency | Net LOC churn | +N / -N | ↑/↓/→ |

---

## Delivered Capabilities (DC)

Total: N DCs (N.N weighted) across N milestones this period.

| Period | DCs | Weighted | Milestones |
|--------|-----|----------|------------|
| ... last 4 weeks ...

**Net-new vs. parity:** N net-new / N parity DCs

---

## DORA Performance

- Deployment frequency: N.N feat merges/week (last 8 weeks)
- Lead time (median): N.N hours
- Change failure rate: N% (fix merges / total merges)
- MTTR: ~0 (structurally N/A for solo dev repo)

---

## Longitudinal Comparison

[If --baseline provided: compare current period vs. baseline period]
[Otherwise: compare current vs. 4-week moving average]

---

## LOC Health

- Production LOC: N (backend=N, web=N, mobile=N)
- Test LOC: N (ratio: N%)
- This period: +N added / -N deleted (net N)

---

## Insights

[2-3 concrete, data-driven observations — e.g.:]
- DC velocity this week (N.N) is N% above the 4-week average (N.N) — strong delivery
- Lead time increased to N hours — check for long-running branches
- Test ratio dropped N pp — prioritize coverage before new features

---

*Report generated by `/productivity-report`. See `.claude/metrics/README.md` for methodology.*
```

## 6. Save Report

Save the report to `.claude/metrics/productivity-reports/YYYY-WNN.md` where `YYYY-WNN` is the current ISO week.

```bash
mkdir -p .claude/metrics/productivity-reports
```

Then write the report file.

## 7. Summary

Print a one-line summary:
> "Report saved to `.claude/metrics/productivity-reports/YYYY-WNN.md` — N DCs this week (N.N weighted), lead time N.N hours."
