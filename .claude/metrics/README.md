# Automation & Productivity Metrics

This directory contains automation usage metrics, productivity measurement data, and sentinel analysis artifacts.

## Files

- `usage-stats.toml` — Canonical aggregated metrics (compiled by `/compile-metrics`)
- `recommendations.md` — Recommendation record table (tracked by automation-sentinel; auto-appended on each `/compile-metrics` run)
- `sessions/` — Per-session delta files (transient; consumed and deleted by `/compile-metrics`)
- `sentinel-report-*.md` — Point-in-time sentinel health reports (archived manually)
- `productivity-reports/` — Weekly productivity reports generated by `/productivity-report`

## How It Works

1. **Collection:** The `track-usage.py` PostToolUse hook writes per-session delta files to `sessions/{branch}.toml` whenever an agent or command is invoked
2. **Aggregation:** `/compile-metrics` runs on `develop` after PRs merge — reads delta files, merges them into `usage-stats.toml`, then deletes the session files
3. **Analysis:** The `automation-sentinel` agent reads `usage-stats.toml`, agent files, and command files to produce a health report and append new recommendations to `recommendations.md`
4. **Commit:** All changes (`usage-stats.toml`, `recommendations.md`) are committed together as `chore: compile session metrics`

## Updating Metrics

Run on `develop` after merging feature PRs:

```bash
/compile-metrics
```

For an on-demand productivity report:

```bash
/productivity-report
```

## DC Weight Reference (ADR-008)

The productivity framework uses **Delivered Capability (DC)** as the atomic value unit. DCs are milestone items from `docs/ROADMAP.phase-*.md` tables.

| MoSCoW Priority | Weight | Notes |
|-----------------|--------|-------|
| Must Have | **1.0** | Core deliverable |
| Should Have | **0.7** | Important but not blocking |
| Could Have | **0.4** | Enhancement |
| Won't Have / Deferred | **0.0** | Not counted |
| *(no Priority column)* | **1.0** | Default — Phase 1 tables lack this column |

**Anti-gaming property:** Splitting a Must Have into two Could Haves reduces the weighted total (1.0 → 0.8). The system penalizes artificial decomposition.

**Non-DC work** (tracked separately as maintenance effort, not in DC count):
- Bug fixes (`fix:` commits)
- Chores (`chore:` commits)
- Refactorings (`refactor:` commits)

**Mobile parity DCs** count as full DCs (real user-facing value on a new platform) but are tagged `parity=true` so reports can separate net-new from port work.

## SPACE Dimension Mapping

| SPACE Dimension | Metric | Source | Automation |
|-----------------|--------|--------|------------|
| **S** Satisfaction | 1-5 score per report | `/productivity-report` prompt | Manual |
| **P** Performance | Deployment frequency (feat PRs/week) | `[dora_metrics]` | Full |
| **P** Performance | Lead time (median hours) | `[dora_metrics]` | Full |
| **A** Activity | DC velocity (weighted DCs/week) | `[dc_timeline]` | Full |
| **A** Activity | Spec throughput (implemented/month) | `[spec_pipeline]` | Full |
| **C** Communication | PR review accept ratio | `[pr_review_quality]` | Full |
| **E** Efficiency | Test/prod LOC ratio | `[productivity]` | Full |
| **E** Efficiency | LOC churn (adds/deletes) | `[loc_churn]` | Full |

## Data Flow

```
Session work
  │
  ▼
/finish-session — commit + quality gates (JaCoCo, E2E, orphan check)
  │
  ▼
PR merge → develop
  │
  ▼
/compile-metrics
  ├── Step 0:  sync-automation-registry.py
  ├── Step 4B: loc_compute.py        → [productivity]
  ├── Step 4C: pr_quality.py         → [pr_review_quality]
  ├── Step 4D: spec_pipeline.py      → [spec_pipeline]
  ├── Step 4F: dc_counter.py         → [dc_timeline] totals
  │           dc_timeline.py         → [[dc_timeline.periods]]
  ├── Step 4G: dora_metrics.py       → [dora_metrics]
  ├── Step 4H: loc_churn.py          → [[loc_churn.periods]]
  └── Step 4E: automation-sentinel   → recommendations.md
  │
  ▼
usage-stats.toml (canonical)
  │
  ├──▶ /productivity-report  — formatted Markdown report with SPACE dimensions
  └──▶ productivity-metrics skill — conversational interpretation & trend analysis
```

See `docs/ARCHITECTURE.md` § ADR-008 for full rationale.
