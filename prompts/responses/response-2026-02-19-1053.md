## The 3 environment variables you'll need to collect

**From Supabase** (after creating a project):
- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`

**Generate yourself** (a strong random string):
- `JWT_SECRET` — must be 256+ bits. Run this: `openssl rand -base64 32`

**From Google Cloud Console** (you already have this for local dev):
- `GOOGLE_CLIENT_ID` — same client ID, but you'll need to add production URLs to the allowed origins/redirects

## Step-by-step order

### 1. Supabase (10 min)

1. Go to [supabase.com](https://supabase.com) → New project
2. Choose a region close to you, set a DB password
3. Once created: **Project Settings → Database → Connection string**
4. Select **"URI"** mode — it gives you: `postgresql://postgres:[YOUR-PASSWORD]@db.xxx.supabase.co:5432/postgres`
5. Break it into parts — that's your `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`

> Flyway will run your migrations automatically the first time the backend starts. No manual SQL needed.

---

### 2. Railway — Backend (15 min)

1. Go to [railway.app](https://railway.app) → New Project → **Deploy from GitHub repo**
2. Select `lucasxf/engineering-daybook`
3. Railway will detect the `backend/Dockerfile` — confirm it
4. Set **root directory** to `backend/`
5. Add environment variables (Settings → Variables):

```
DB_HOST=db.xxx.supabase.co
DB_PORT=5432
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=your-supabase-db-password
JWT_SECRET=your-generated-secret
GOOGLE_CLIENT_ID=your-google-client-id
SERVER_PORT=8080
```

6. Railway will build and deploy. You'll get a URL like `https://engineering-daybook-production.up.railway.app`
7. Test it: `https://your-railway-url/api/v1/health` → should return `{"status":"UP"}`

---

### 3. Vercel — Web (5 min)

1. Go to [vercel.com](https://vercel.com) → New Project → Import `lucasxf/engineering-daybook`
2. Set **root directory** to `web/`
3. Framework: **Next.js** (auto-detected)
4. Add environment variables:

```
NEXT_PUBLIC_API_URL=https://your-railway-url/api/v1
NEXT_PUBLIC_GOOGLE_CLIENT_ID=your-google-client-id
```

5. Deploy. You'll get a URL like `https://engineering-daybook.vercel.app`

---

### 4. Google OAuth — Add production URLs (5 min)

In [Google Cloud Console](https://console.cloud.google.com) → your OAuth app → **Authorized JavaScript origins** and **Authorized redirect URIs**, add:

```
https://engineering-daybook.vercel.app
https://engineering-daybook.vercel.app/en
https://engineering-daybook.vercel.app/pt-BR
```

---

### 5. CORS — Critical pre-deployment fix

The backend CORS config is hardcoded to `http://localhost:3000` (`SecurityConfig.java:72`).
This will block the Vercel app from talking to the backend.

**Fix needed:** Read the allowed origin from an env var (`ALLOWED_ORIGINS`) so you can set
`https://engineering-daybook.vercel.app` on Railway without touching code.
