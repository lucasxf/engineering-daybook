# Mobile Visual Parity Migration Plan — Library at Dusk

## Context

The learnimo mobile app (Expo/React Native) uses an indigo/gray Tailwind-derived palette while the web app has migrated to "Library at Dusk" (parchment backgrounds, ember-orange CTAs, deep navy dark mode). A `mobile-design-system` skill was created (Step 1 of the execution sequence) encoding the target tokens, component recipes, and typography. This plan covers **Steps 2–6**: updating `tokens.ts`, loading custom fonts, updating all 11 shared components, and patching all 10 screens to achieve visual parity. No domain logic changes.

## 6. Risks

| # | Risk | Impact | Mitigation |
|---|------|--------|------------|
| 1 | **Test breakage from palette swap** — Tests asserting specific hex values (`'#6366F1'`) break when palette changes | Medium | Before merging S0.1, grep all test files for hardcoded hex values from the old palette. Update assertions to new values in the same commit. |
| 2 | **Font loading adds cold-start delay** — `useFonts` + SplashScreen hold may be noticeable | Low | Fonts are bundled at build time (not fetched over network). Expect ~100ms overhead. Test on real device. If unacceptable, fonts can be preloaded in a native module. |
| 3 | **Dark mode `tagPillBg` uses rgba** — `rgba(43,74,120,0.35)` may render differently over different backgrounds (list item vs modal vs card) | Medium | Test tag pills in all contexts: FeedScreen cards, LearningDetailScreen tag modal, LearnerProfileScreen. If transparency causes visual issues, switch to an opaque approximation (`#162A46`). |
