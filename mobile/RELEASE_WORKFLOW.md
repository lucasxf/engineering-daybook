# Android Release Workflow

> **IMPORTANT:** Always follow this sequence before every Play Store submission.
> Skipping the preview smoke test is how release-only native crashes ship undetected.

---

## Step 1 — Regenerate native directory

```bash
cd mobile
npx expo prebuild --clean --platform android
```

This wipes `android/` and regenerates it from scratch, then runs all 4 config plugins automatically:
- `withSecureStoreBackupRules` — copies `res/xml/` backup rule files from `expo-secure-store`
- `withCleanPermissions` — removes `RECORD_AUDIO`/`SYSTEM_ALERT_WINDOW`, pins storage `maxSdkVersion=28`
- `withReleaseSigning` — injects `signingConfigs.release` (reads env vars) and removes debug `signingConfig` from release buildType
- `withActivityPin` — forces `androidx.activity:1.9.3` for AGP 8.8.x + compileSdk 35

**Never skip this step.** Manual patches to `android/` are wiped on every clean prebuild. All patches must live in `mobile/plugins/`.

---

## Step 2 — Run unit tests

```bash
npm run test:coverage
```

Must pass with ≥ 80% line coverage. Fix failures before continuing.

---

## Step 3a — Local build path (Windows / no macOS)

Use the automated script. It handles versionCode bump, prebuild, signing, and bundleRelease in one step:

```bash
# Ensure the keystore file exists at mobile/@lucasxf__learnimo.jks
# (download from EAS if needed: eas credentials --platform android → Keystore → Download)
# Set signing env vars (copy from mobile/.env.signing.example → mobile/.env.signing):
source mobile/.env.signing
cd mobile
bash scripts/build-release.sh
```

The script:
1. Reads `android.versionCode` from `app.json` and bumps it by 1 (source of truth — never edit `build.gradle` directly)
2. Bumps the patch in `version` (e.g., `1.0.2` → `1.0.3`)
3. Runs `expo prebuild --clean --platform android` (wipes and regenerates `android/`)
4. Copies the keystore into `android/app/` **after** prebuild (prebuild wipes `android/`, so copying before is useless)
5. Runs `./gradlew bundleRelease`

Output AAB: `android/app/build/outputs/bundle/release/app-release.aab`

> **Note:** `app.json` is the only durable location for `versionCode` — `android/app/build.gradle` is regenerated by prebuild and always reset. The script bumps `app.json` before prebuild so the new value is baked into the regenerated Gradle file.

---

## Step 3b — EAS Cloud build path (Preview smoke test gate)

```bash
eas build --platform android --profile preview
```

When done, install on emulator:
```bash
eas build:run --platform android --profile preview
# or: download APK from expo.dev → Builds, drag onto emulator
# or: adb install /path/to/downloaded.apk
```

**Verify:**
- [ ] App launches from home screen icon (not from Android Studio)
- [ ] Splash screen + Onnim icon appear
- [ ] Login screen loads within ~2 seconds
- [ ] Cold start works: kill app → relaunch → same result

**Do not proceed to production if any of the above fail.** This is the gate that catches release-only native crashes (e.g., missing XML resources, wrong signing, manifest merger errors) that Maestro E2E misses because it runs on debug builds.

---

## Step 4 — EAS Production build

```bash
eas build --platform android --profile production
```

---

## Step 5 — Submit to Play Store

```bash
eas submit --platform android --profile production
```

This uploads the AAB to the Play Store internal track. Promote to production via the Play Console after internal testing.

## Why Current Tests Don't Catch Release Crashes

**The crash-on-launch class of bug evades all current automated tests.** Here is why and what to do about it.

### Why current tests miss it

| Test type | What it tests | Why it misses |
|-----------|--------------|---------------|
| Jest unit tests | Pure TS logic, no native | Run in Node env — no Android at all |
| Maestro E2E flows | User flows on a live device | Run against **debug builds** via `expo run:android`. Debug builds load JS from Metro (not a compiled bundle) and don't trigger `Resources.NotFoundException` from missing XML |
| EAS Preview build | Produces a distributable APK | ✅ **Would catch this** — if installed and launched before every submission |

### The fundamental gap

Debug builds (`expo run:android`) and release builds (`eas build --profile production`) use different code paths. The backup-rules crash only manifests in release mode because Android enforces `fullBackupContent` and `dataExtractionRules` XML references at install time for release builds. Maestro runs on debug — it is structurally blind to this class of bug.

### What prevents it

1. **EAS Preview smoke test (Step 3b above):** Run before every production submit. If the app doesn't reach the login screen, do not submit.

2. **Config plugins (permanent fix):** All Android patches are encoded as plugins in `mobile/plugins/`. `expo prebuild --clean` followed by plugins produces a correct native directory every time. Never patch `android/` directly.

3. **Release-mode Maestro test (future):** Run `maestro test e2e/auth-login.yaml` against the EAS Preview APK. Requires a CI runner with Android emulator access.
